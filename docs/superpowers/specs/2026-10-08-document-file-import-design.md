# v0.2.0 Markdown/TXT 文件导入设计

## 目标与范围

让用户把本地 Markdown 或 TXT 学习资料导入现有知识库。在保存前，用户能预览并修改标题、正文和标签；保存后的文档继续参与现有检索、编辑和删除。导入仅保存解析后的正文和原文件名，不保存文件二进制内容。

本阶段支持 `.md`、`.markdown` 和 `.txt`。PDF、分块、重复内容检测和向量索引属于路线图后续工作，不纳入本次交付。

## 用户流程

1. 用户在“添加学习资料”区域选择一个文件。手动输入文档的现有流程继续可用。
2. 前端把文件作为 `multipart/form-data` 发送到 `POST /api/documents/preview`。
3. 后端校验并解码文件，返回建议标题、正文和原文件名。前端把这些值填入现有表单，允许用户修改并添加标签。
4. 用户点击“保存文档”。前端通过现有 `POST /api/documents` 提交标题、正文、标签，以及可选的原文件名。保存成功后刷新当前搜索结果。
5. 用户如果重新选择文件，新预览替换尚未保存的导入草稿；取消或清空文件选择不会自动删除已保存文档。

## API 与数据模型

新增 `POST /api/documents/preview`，请求包含名为 `file` 的文件字段。成功返回：

```json
{
  "title": "向量检索基础",
  "content": "# 向量检索基础\n...",
  "sourceFilename": "向量检索基础.md"
}
```

现有 `POST /api/documents` 的 JSON 请求增加可选 `sourceFilename`，文档响应也增加可空的同名字段。`PUT /api/documents/{id}` 仍只编辑标题、正文和标签，保留已有原文件名；手动创建的文档在响应中返回 `null`。

用 Flyway V3 给 `knowledge_documents` 增加可空的 `source_filename VARCHAR(255)`。导入保存使用现有文档服务和事务，不另建文件表或文件存储。原文件名仅用于显示来源，不参与路径访问。

## 后端解析与校验

建立窄接口 `DocumentTextParser`，由文件扩展名选择 Markdown 或 TXT 实现；两个实现当前都严格按 UTF-8 解码并保留原有文本与 Markdown 标记。解析逻辑集中在导入服务，控制器只处理 HTTP 转换。接口为将来增加 PDF 解析器预留扩展点。

- 仅接受 `.md`、`.markdown`、`.txt` 扩展名，大小写不敏感；不依赖浏览器发送的 MIME 类型判断文件格式。
- 文件最多 1 MiB（1,048,576 字节）。同时配置 Spring multipart 上限，并在解析服务中校验大小。
- 接受 UTF-8 和 UTF-8 BOM；遇到非法 UTF-8 字节序列直接拒绝，不使用替换字符静默转换。
- 解码后正文不得全为空白，长度不得超过现有文档正文上限 100,000 个 Java 字符。
- 原文件名先去除客户端可能携带的路径，再验证非空、长度不超过 255 个字符；建议标题由去掉扩展名的文件名生成，超出 200 字符时截断。
- 预览不会写数据库。最终保存仍由现有请求校验标题、正文、标签和原文件名。

不支持的扩展名返回 HTTP 415；文件超过限制返回 413；空文件、非法编码、无效文件名或正文超限返回 400。响应使用现有 API 错误结构，前端展示可理解的中文错误。任何解析失败都不创建文档。

## 前端交互

在现有创建表单增加文件选择控件、导入状态和来源文件名提示。选择文件后显示“解析中”，成功时把建议标题和正文填入可编辑字段；用户可以在保存前修订内容。保存按钮沿用现有文档创建操作和状态反馈。重新选择文件时清除旧的导入错误；上传失败时保留当前表单草稿，避免丢失手动输入内容。预览以文本表单呈现 Markdown 源文，不渲染文件内 HTML。

保存成功后清空表单和来源文件名。文档列表显示来源文件名；手动创建的文档不显示来源标记。

## 验证与验收

- 后端测试覆盖三种扩展名、中文与 BOM、非法 UTF-8、空文件、超大文件、不支持的扩展名、正文超限和原文件名规范化。
- API 测试验证预览不落库、预览后保存会带来源文件名、手动创建返回空来源、编辑保留来源、旧文档经迁移后仍可读取。
- 前端组件测试验证选文件后预览、修改后保存、解析错误保留草稿，以及来源提示。
- 运行后端测试、前端测试与构建，并检查 GitHub Actions 通过。最终在 GitHub 仓库中更新 README、路线图和版本号。

完成标准：用户可以在浏览器选择有效 Markdown/TXT 文件，看到可编辑预览，保存后在现有列表和搜索中找到该文档；无效文件不会写入数据库，错误可读，现有手动创建与编辑流程继续通过测试。
